<a id="principles"></a>
## 1. 设计原则

1. **内容优先**：界面表达内容之间的关系，不把框架结构画成主角。
2. **连续表面**：导航、内容和操作区应像同一张工作面，而不是多个盒子拼接。
3. **留白分组**：优先用间距、字号、字重和轻微表面色建立层级。
4. **减少重复**：左侧已经选中的名称、标签本身已经表达清楚的说明，不在右侧重复展示。
5. **克制边界**：线条只用于控件可操作性的必要提示，不用于表示页面结构。
6. **安静反馈**：状态通过颜色、位置和短暂动效表达，避免高对比描边与装饰性阴影。

<a id="layout"></a>
## 2. 布局与融入

主从栏必须使用同一视觉基底：

- 左侧导航和主内容区之间不得使用通栏竖线。
- 导航与主内容必须有可感知的表面层级：导航使用 Rail 底色，主内容使用 Paper 底色，但不使用分割线。
- 导航选中态使用浅色底、胶囊或字重变化，不使用分割线强调边界。
- 内容分类选中态必须额外使用对应类型色的 2px 轮廓：文章蓝、贴图洋红、视频橙、音频青；发布队列使用绿色。轮廓不得改变布局尺寸。
- 导航与内容的左缘通过对齐和留白形成关系，参考工作台首页的侧栏与内容区。

设置采用双栏结构：

- 左栏是设置分类，只显示分类名。
- 每条设置分类必须占满 Rail 内容宽度，选中底色和轮廓不得只包住文字。
- 设置窗口使用固定宽高，不随当前分类内容伸缩。
- 左栏沿用应用首页的 236px Rail：相同品牌入口、边距、行高、圆角和选中态。
- 左栏顶部先显示“设置”主标题，再显示“九漾 Onda”品牌副行；两层文字分别使用主文字色和次要灰。
- 右栏是嵌入 Rail 的 Paper 工作区，四角使用同一组圆角；不得退化成与 Rail 齐平的直角面板。
- 右栏直接显示当前分类的控件，不重复显示已选分类名称。
- 分类名称本身足够清楚时，不再增加解释性副文案。
- 基础设置使用逐行设置项，不使用并排卡片。
- 设置不提供底部“完成”按钮；用 Esc 或点击弹层外部关闭。
- 浏览器扩展安装不使用外层卡片或分组底色；Chrome、Edge 和手动安装都作为基础设置中的连续操作行，保留行级 hover、状态和右侧动作。
- 选择 Chrome 或 Edge 后直接在该浏览器打开安装入口；安装完成后通过本机宿主自动连接，不显示地址、配对码或“我已连接”确认。
- Chrome、Edge 行在安装、等待和失败期间原地更新状态；“已连接”使用绿色文字或状态点，不再提供日常配对管理按钮。
- 手动安装只说明下载、开发者模式和加载步骤，必须提供 GitHub Releases 下载入口，安装完成后同样自动连接。
- 扩展连接归属于本机发布服务，而不是某个前端。桌面端与 Obsidian 共用同一条扩展连接；连接细节只在帮助或悬浮提示中出现。

编辑与预览属于同一工作面：

- 编辑区和预览区共享外框和底色关系。
- 两栏之间不得使用明显竖线。
- 预览列不得再拥有独立的大面积背景块；Paper 应连续铺满编辑与预览两栏。
- 正文使用适合中文长文阅读的固定最大宽度，并在可用空间内与预览共同居中；短稿不得铺满整个窗口形成失控的横向空白。
- 编辑工具栏融入正文表面，不套独立卡片、边框或阴影。
- 设备预览本身保留必要圆角和轻微阴影，用于表达“手机视图”，而不是表达两栏分区；短内容时预览随内容收高，不预留大块空屏。
- 可用轻微背景差、间距和局部表面形成区域感。
- 预览是内容的另一视角，不应看起来像独立应用。

<a id="dividers"></a>
## 3. 分隔线与边界

硬约束：

- 页面头部、导航边界、左右主栏、编辑/预览边界、底部操作区不得使用通栏分隔线。
- 不得用水平线把设置分区切成多段。
- 不得用多层卡片和边框堆叠表达层级。

允许使用边界的情况：

- 输入框、选择器、复选控件等需要明确操作边界的控件。
- 独立可点击或可选择的卡片。
- 浮层、菜单和对话框。
- 键盘焦点环、选中态和错误态。

移除线条后必须保证：

- 仍能通过间距和标题层级理解分组。
- 交互元素仍有清楚的 hover、focus 和 selected 状态。
- 不因追求“融入”而降低可访问性对比度。

<a id="surfaces"></a>
## 4. 表面与层级

| 层级 | 用途 | 表现 |
|---|---|---|
| Paper | 页面与主内容 | 主导底色，不再嵌套卡片 |
| Rail | 导航、辅助区域 | 与 Paper 的细微明度差 |
| Hover | 可交互行、选项 | 短暂表面变化 |
| Selected | 当前分类、当前选择 | 浅 accent 底或平台色淡底 |
| Overlay | 菜单、Popover、Modal | 轻阴影，不与页面结构线同时使用 |

阴影只用于真正浮起的临时层。静态区域应依靠留白和表面色，不使用悬浮卡片阴影。
右侧大圆角主工作区在代码中称为 `WorkspaceSurface`，它是页面结构表面，不是 Card；空态内容使用 `EmptyState`。

<a id="settings"></a>
## 5. 设置页

- 使用左右双栏，左栏只列分类名称。
- 分类固定为基础设置、平台账号、默认发布；主题属于基础设置，不单设“外观”分类。
- 右栏不重复分类名称，不加“主题与显示”“扩展与内容目录”等显而易见的副标题。
- 基础设置必须是逐行布局：
  - 主题一行；
  - 浏览器扩展的 Chrome、Edge 和手动安装各占一条完整操作行；
  - 内容目录一行；
  - 资源目录一行。
- 每行由图标、主名称、当前状态和右侧动作组成。
- Chrome、Edge 行必须在右侧提供“安装”动作，安装后原地切换为已连接状态；不恢复“浏览器选择”下拉框。
- 内容目录的动作统一为“选择目录”。
- 资源目录展示实际保存目录，支持内容目录内的相对路径和目录外绝对路径；Obsidian 的附件位置由 Obsidian 自己管理。
- 没有补充信息时不显示空描述行。
- 扩展 popup 只显示连接状态、当前任务和打开发布队列；不提供地址、短码、撤销配对等日常管理字段。

<a id="editor"></a>
## 6. 编辑与预览

- 编辑器和预览共享同一个工作台背景与顶部层级。
- 写作列是主动作，预览列是辅助视图；两者通过宽度和表面区分，不通过硬分隔线切裂。
- 长文预览保持独立滚动，但滚动边界依靠布局容器，不画线。
- 未保存、冲突、外部修改等状态应贴近内容出现，不使用大面积警告块打断。
- Obsidian 只保留“预览”和“默认”两个视图；“发布”不是独立 Tab。
- 发布动作固定在预览底部，一次点击直接发送当前已选平台；发布中状态以紧凑的平台状态条回到同一视图。
- 本机服务与浏览器扩展健康度在工具条中只用状态色表示，并以可读提示说明当前是否可用；不得逐行展示地址、浏览器版本或扩展版本。
- 连接状态色固定为：绿色可用、黄色等待、红色不可用；颜色必须同时提供 `aria-label` 和悬浮提示。

<a id="content-media"></a>
## 7. 内容类型与媒体

不同内容类型必须有不同视觉结构：

| 类型 | 展示方式 |
|---|---|
| 文章 | 标题、正文和图片按 Markdown 原顺序流动；图片在原文位置或文末位置，不自动提升为顶部图集 |
| 贴图 | 图片按出现顺序组成图集；文本与图集分开 |
| 视频 | 使用单个主视频或有序视频列表，不套用图片图集 |
| 音频 | 使用播放条或波形，不套用图片图集 |

平台预览只压缩布局，不改变内容类型的事实结构。

图片必须作为真实媒体内容直接渲染：

- 只依赖 Markdown 中的路径或 URL，不要求图片位于固定目录。
- 不套卡片、占位底色、固定 16:9 容器或装饰边框。
- 保持图片自身宽高比；只限制最大展示宽度和高度。

<a id="controls"></a>
## 8. 控件

- React Web 的可见交互控件必须使用 HeroUI：Button、Input、SearchField、Textarea、Checkbox、Select、Dropdown、Modal、Popover、Drawer。
- 通用图标必须使用 `reicon-react`。
- 例外仅限品牌 Logo、平台和浏览器品牌图标、真实媒体播放表面、canvas/视频内容、contenteditable 序列化 HTML，以及 Reicon 缺失的专属图形。
- 原生下拉框、checkbox、文本框不得用于新的 Web 业务界面。
- 控件移植后必须在真实主题中验证尺寸、行高、焦点环、hover 和禁用态。
- 对话框中的“取消”必须保持安静表面：hover 只能使用 Hover 色和主文字色，不得反转为深色实心按钮。

<a id="copy"></a>
## 9. 文字与信息密度

- 文案使用简洁中文，优先动词和事实。
- 删除重复说明：标签已表达的内容不再追加同义句。
- 删除显而易见的操作解释；只有条件、风险、后果或不可逆动作需要提示。
- 状态文案必须来自任务或账号事实，不能用装饰性数字填充。
- 按钮使用明确动作，例如“选择目录”“安装扩展”“保存发布结果”。

<a id="theme"></a>
## 10. 主题

- 必须支持浅色、深色和跟随系统。
- 首屏渲染前设置 `data-theme`，避免闪烁。
- `data-theme` 必须保存用户偏好（`light` / `dark` / `system`），不得把 `system` 在启动时解析成 `light` 或 `dark` 后持久化。
- “跟随系统”由 `prefers-color-scheme` 直接解析；不得只依赖一次性 `matchMedia` 回调，否则运行时切换可能失效。
- 根元素必须同步 `color-scheme: light | dark | light dark`，让原生控件和滚动条跟随。
- 手动选择浅色或深色后，不继续跟随系统变化。
- Web、Obsidian 原型和浏览器扩展原型使用同一主题语义。

<a id="states"></a>
## 11. 状态与动效

- 选中态：浅 accent 底或平台色淡底，可附加小勾。
- 运行态：进度水位或细进度条，不使用持续闪烁的大面积颜色。
- 等待态：中性底 + 明确状态词。
- 错误态：统一的错误色和结构化原因。
- 动效时长 150–250ms；支持 `prefers-reduced-motion`。
- 不以无限动画表示普通静态状态。

<a id="accessibility"></a>
## 12. 可访问性

- 正文和控件文字对比度至少 4.5:1。
- 所有交互控件必须有键盘焦点态、可读名称和足够的点击区域。
- 移除视觉分隔线后，仍需通过标题层级、留白和语义标签保持可理解性。
- 不使用颜色作为唯一状态信号；颜色必须与文字、图标或位置共同表达。

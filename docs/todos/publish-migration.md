# 浏览器扩展正式发布迁移

> 状态：代码迁移完成，真机验收进行中。
> 关联架构：[浏览器扩展](../design/architecture.md#extension)、[发布任务](../design/architecture.md#publish)、[账号同步](../design/account-sync.md)。

## 目标

把已有平台发布能力从旧 CDP/专用 profile 路径迁移到用户日常浏览器里的 Onda MV3 扩展，并完成真实发布验收。

## 本轮范围内

1. **公共发布任务运行时**
   - 单扩展执行通道下的发布任务串行调度。
   - 任务派发确认、进行中任务持久化、后端或扩展重连恢复。
   - 超时、取消、聚焦平台标签页、关闭留存标签页。
   - 防止同一任务因断线重连或重复派发而执行两次。
2. **公共扩展发布层**
   - 标签页生命周期、页面上下文执行、文件注入、素材传输、事件上报、回执和人工确认只实现一次。
   - 平台 driver 只实现各自的页面入口、字段填充、文件上传和草稿/发布语义，不复制浏览器连接与任务状态机。
   - 驱动随扩展打包，不接受服务端下发任意脚本。
   - 发布结果区分成功、等待人工、明确失败和结果未知。
3. **全部 active 平台驱动**
   - 在同一轮迁移中接入微信公众号、微博、小红书、X、知乎、豆瓣、即刻、小宇宙、喜马拉雅、荔枝。
   - 各平台直接复用旧平台包中已经验证过的发布知识，只把执行上下文从 CDP 改为 MV3 扩展公共运行时。
   - 同一平台按内容类型和发布通道分别验收，不能用账号验证成功代替发布验证。
4. **素材上传复用**
   - 以图片内容 hash、平台、账号和用途为缓存键。
   - 保存平台远端素材引用，后续发布优先复用，避免重复上传。
5. **发布结果**
   - 自动回执、人工填写链接和无公开链接三种结果都写入任务。
   - 草稿型平台返回草稿链接，并保留需要用户继续操作的平台标签页。
6. **验收**
   - 每个平台至少完成一次真实发布或草稿真机验证。
   - 覆盖登录失效、断线重连、重复点击、超时、结果未知和人工确认。

## 当前代码状态

- 浏览器扩展连接、Native Messaging 自动配对、心跳和 10 个 active 平台账号验证已落地。
- `apps/extension/src/drivers.ts` 已注册微信公众号、微博、小红书、X、知乎、豆瓣、即刻、小宇宙、喜马拉雅、荔枝驱动。
- 发布任务已串行执行，扩展持久化队列、进行中任务和未确认结果；重连恢复、取消、tab 聚焦/关闭、Service Worker 保活和服务端结果确认已落地。
- 所有平台默认只填充、不提交；X 与知乎也不会默认代点发布。成功或等待确认后保留平台标签页，只有用户主动取消时才关闭本次任务创建的标签页。
- 发布快照会把本地媒体转为短期签名 URL；扩展按内容 hash、平台、账号和用途复用 `.onda/state/uploads/` 中已确认的平台素材引用。
- 旧平台包只作为平台知识与选择器参考，不再作为产品发布回退通道。

## 明确延期

以下事项不参与本轮正式发布迁移，也不作为本轮完成标准：

- 豆包或其他网页生图能力。
- Agent 接入、Agent token、MCP server 和 CLI。
- B站、头条号、百家号、抖音等 `planned` 平台。
- 不阻塞发布的内容 watcher、软编辑租约和三方冲突副本。
- Obsidian 插件 token 配对、Agent 审计和通用浏览器自动化能力。
- Chrome Web Store / Edge Add-ons 正式上架。

## 实施顺序

1. 建立一次公共发布任务可靠性与扩展执行协议。
2. 建立公共页面执行、文件注入、素材上传复用和回执能力。
3. 基于旧平台包批量接入全部 active 平台 driver。
4. 以微信公众号文章草稿完成首个端到端验收。
5. 对其余 active 平台并行进行真机验收；平台差异只修对应 driver，不改公共运行时。

## 完成条件

- 所有本轮 active 平台通过真实 Chrome 发布或草稿验证。
- 任务重启、断线、超时、取消和人工确认路径可验证。
- 同一素材重复发布不会重复上传。
- 旧 CDP 发布路径不再作为产品回退通道。
- 文档明确区分已迁移平台、待迁移平台和延期能力。

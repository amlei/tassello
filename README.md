# tassello · 铺稿

多平台内容发布工作台的原型。写一次，铺到多个平台。

**tassello** 是意大利语里的「拼片」——嵌进镶嵌画、构成整幅画面的那一小块。一份稿子被排成多种版面、分发到不同渠道，正像一块块拼片嵌成同一幅画：远看是一件作品，近看是许多块各自成形。整套界面语言也从这种「装配」的手工感里来——版面标记、色标条、稿纸网格。

> 本仓库是 **PM / PoC 阶段的原型**，用于验证信息架构、内容类型抽象，以及「发布不阻塞界面」的交互模型。**不对接任何真实平台，所有发布均为前端模拟。**

## 核心判断

这个应用的主体不是平台，而是内容本身。平台是内容的出口，不是导航对象。用户打开它，第一眼看到的应该是「我有哪些稿子」，而不是「我连了哪些平台」。

## 内容类型

五种类型是一等公民，各有独立的字段与编辑形态：

| 类型 | 字段 |
|---|---|
| 长文 | 标题、Markdown 正文、摘要、标签 |
| 短文 | 标题（选填）、正文、标签 |
| 贴图 | 标题、描述、图片素材、标签 |
| 视频 | 标题、简介、视频素材、封面、标签 |
| 音频 | 标题、简介、音频素材、时长、标签 |

## 关键设计

**平台矩阵驱动 UI。** 平台数据声明各自支持的内容类型与硬约束（字数上限、图片张数等）。不支持当前类型的平台禁用并给出理由；内容超限时行内提示；违反硬约束的发布任务会以**可归因的确定性错误**失败，而不是随机失败。

**发布绝不阻塞界面。** 点击发布后任务立刻入队，界面立即可用。状态分两层呈现：

- 顶部细进度条：只解决「后台还在跑、不用守着」，点击跳转任务页
- 任务页 `/tasks`：状态的真相源，承载阶段、进度、错误与重试

发布链路分四个阶段：渲染排版 → 上传素材 → 填充编辑器 → 等待人工确认。

**文案即界面。** 空状态与错误是引导而非情绪，动作即结果（按钮「发布」→ 提示「已发布」）。

## 技术栈

- Next.js 16.3.4（App Router / Turbopack）
- React 19.2 + TypeScript 7.0.2
- Tailwind CSS 4
- shadcn/ui（`radix-nova` 基座）+ AI Elements
- reicon-react（界面图标）、reicon-brands（平台品牌图标）

纯前端，无后端与数据库。状态用 React Context + `useReducer` 管理并持久化到 localStorage。

> **TypeScript 7 与 ESLint**：`typescript-eslint` 目前不支持 TS 7，因此按 TypeScript 官方文档的 side-by-side 方案，额外以别名 `typescript6` 装了 TS 6，并在 `eslint.config.mjs` 中把 ESLint 进程内对 `typescript` 的解析重定向到 TS 6。项目本身仍是 TS 7。

## 开始

```bash
npm install
npm run dev      # http://localhost:3000
```

```bash
npm run build      # 生产构建
npm run typecheck  # tsc --noEmit
npm run lint       # eslint
```
